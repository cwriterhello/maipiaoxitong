## 各业务流程及技术难点

### 1. 用户注册/登录流程

**技术难点**：高并发注册时的缓存穿透问题

- 使用布隆过滤器防止无效查询 UserService.java：36
- 分库分表策略：用户表按ID分片，手机号和邮箱表按对应字段分片

### 2. 浏览节目流程

**技术难点**：突发流量下的查询性能

- 多级缓存设计：本地缓存 + Redis缓存
- Elasticsearch支持节目搜索

### 3. 选座购票流程（核心难点）

**技术难点**：高并发下的座位竞争和库存扣减

#### 座位锁定机制

- 使用Lua脚本原子性作：将座位从NO_SOLD状态移动到LOCK状态
- 库存扣减与座位状态变更在同一事务中完成

#### 并发控制策略

- **本地锁 + 分布式锁双重保护**：按票档ID排序加锁，避免死锁
- **防重提交**：注解防止重复下单`@RepeatExecuteLimit`

### 4. 订单创建流程（技术亮点）

**技术难点**：高并发下的订单处理能力

#### 双路径订单创建架构

- **同步路径**：正常流量下使用Feign RPC调用
- **异步路径**：高并发场景使用Kafka消息队列

#### 关键设计决策

- **消息延迟阈值**：Kafka消费者拒绝处理超过5秒的延迟消息
- **分布式ID生成**：使用UidGenerator生成分片友好的订单号

### 5. 支付流程

**技术难点**：支付状态一致性

- 分布式锁保护支付操作：注解`@ServiceLock`
- 缓存与数据库数据一致性保证

### 6. 订单管理流程

**技术难点**：分库分表下的查询性能

- 订单表按订单号分片，避免跨库查询
- 用户订单列表查询优化

## 技术难点总结

| 业务流程   | 核心技术难点       | 解决方案                  |
| ---------- | ------------------ | ------------------------- |
| 选座购票   | 座位竞争、库存扣减 | Lua脚本原子作、双重锁机制 |
| 订单创建   | 高并发处理能力     | 同步/异步双路径架构       |
| 用户注册   | 缓存穿透           | 布隆过滤器                |
| 数据存储   | 海量数据存储       | 分库分表策略              |
| 系统稳定性 | 服务雪崩           | 熔断保护、多级缓存        |
